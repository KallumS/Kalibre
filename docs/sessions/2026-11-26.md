## 1.2.0: plug-in pictures, folding headings (0138)

- **Headings fold**: click one in the Plug-ins tab; ▸ when folded, ▾ open,
  the count kept; remembered between starts. A search shows what it finds,
  folded or not.
- **Pictures** under each plug-in's name, four rows tall; **Pictures**
  beside Scan hides them, remembered. Kept in Plug-in Pictures in Kalibre's
  library, one PNG per maker and name (its formats share it).
- **Take Pictures** in the Plug-in Manager (Stop Taking Pictures while it
  runs; right-click > Take Their Pictures Again); the **camera button** on a
  plug-in's panel. A plug-in that closes Kalibre mid-picture is passed over
  after.
- The picture is read from the screen by each system's own call (X11,
  PrintWindow, the window server), since a plug-in's window is a native view
  Kalibre never draws. Tested on Linux with a fake plug-in that draws two
  colours: the picture has both, where they are.
- CI's first run failed on the Mac (Carbon's `Component`) and Windows
  (GDI's `Rectangle`): JUCE's names written in full in those two files.
- Renders: 31 (`docs/guide/browser-plugins.png`, with pictures), 31 folded
  (`docs/guide/browser-plugins-folded.png`), 15 (`docs/guide/plugin-manager.png`,
  Take Pictures), the camera button (`docs/guide/camera-button.png`).

## 1.3.0: Kalibre on Linux (0139)

- It already built and ran on Linux (CI's tests and renders). Added: a
  download (Kalibre-Linux.tar.gz, built on Ubuntu 22.04, with `install.sh`
  for the applications menu and `.kalibre` songs); LV2 and LADSPA besides
  VST3 and CLAP; JACK besides ALSA; Linux's words and menus (File >
  Settings, Help > About, File > Quit on Ctrl+Q, Show in File Manager);
  plug-in windows cut to their panel with X's SHAPE.
- Tried with a VST3 and an LV2 built from JUCE in this container and the
  LADSPA SDK's examples. That found two things, both fixed: asking a VST3 to
  draw smaller (as on Windows) made it shrink towards nothing, so on Linux a
  plug-in is cut, never shrunk; and X's default error handler ended the
  program on the resulting error, so Kalibre now sets one that notes X's
  errors and carries on.
- The user guide's pictures stay in the Mac's words wherever they're drawn.
- Tests: 260 core, 294 app on Linux.

## 1.3.1: Take Pictures' crash on the Mac, and no report (0140)

- The musician's Mac quit during Take Pictures with no Kalibre report;
  macOS's report: a bad memory access in `objc_autoreleasePoolPop` at the end
  of a message. The picture-taker deleted each plug-in in the message that
  closed its window; the engine never does. Now the plug-in is let go of 2 s
  later, in a message of its own. A test failed first (deleted in the same
  message) and passes.
- No report because a plug-in (copy protection, likely) had put its own
  signal handler in Kalibre's place. Now each start notes itself and quitting
  clears it; a start after an unexpected end with no report brings in
  macOS's from ~/Library/Logs/DiagnosticReports, and names the plug-in whose
  picture was being taken.

## 1.3.2: network MIDI's count
