## Not built: two that need the user's say

**All the Mac's cores.** Kalibre plays everything in one audio thread: JUCE's
graph runs each track's plug-ins one after another, so two heavy plug-ins on
two tracks share one core while the others wait. Logic, Live and Bitwig run
tracks side by side on all the performance cores, in the audio device's
"workgroup" so macOS treats them as audio. Doing that here: each track that
takes no other track's sound (not a folder, return or sidechain target)
processed on its own worker thread, joined to the device's workgroup, ahead
of the main graph, which then only mixes; plug-in delay compensation and
automation as now. A day's careful work, and it needs trying on the Mac with
real plug-ins. The figure shown is how much of each buffer's time the audio
takes: a bigger buffer (512) lowers it while mixing.

**Sandboxing.** A plug-in crashing while it plays still takes Kalibre down
(scanning is already safe, 0047). Sandboxing runs plug-ins in helper
processes and sends the sound to and fro each buffer, as Bitwig does. The
cost: a little more CPU and, on the Mac, a plug-in's window belongs to the
helper, so it can't sit inside the rack (0058) without private Apple
interfaces: it would be a window of its own, beside Kalibre's. Bitwig lets
you choose per plug-in. Proposed: per plug-in (right-click > Run in Its Own
Process), off by default, for the ones that crash; with the crash reports
(0073) naming the culprit first.
