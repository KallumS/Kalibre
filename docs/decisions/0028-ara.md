# 0028. ARA plug-ins read the track's audio clips

## Context

Melodyne and other ARA plug-ins analyse and edit audio they read themselves,
rather than audio played into them.

## Decision

When an ARA plug-in is on a track and its ARA switch is on (the default),
Kalibre starts an ARA document for it (JUCE's ARA host helpers, the ARA SDK
2.3.0): one musical context with Kalibre's tempo and time signatures, one
region sequence for the track, an audio source per file and a playback region
per audio clip, placed where the clip is (track delay included). The track's
source stops playing those clips; the plug-in plays them. Regions are rebuilt
only when the clips or tempo change, with the plug-in unprepared and the graph
paused, as ARA asks. The plug-in's edits are saved in the project as an ARA
archive (`Device::araState`) and restored onto objects with the same ids.

## Consequences

- Built on the Mac only (`KALIBRE_ARA`, on for Apple); it compiles on Linux too.
- Not yet tried with Melodyne: needs the user's Mac.
- Each ARA plug-in instance has its own document; Melodyne's multi-track
  editing across tracks would need one shared document per plug-in.
- Warped and reversed clips are given to the plug-in as their plain audio.
